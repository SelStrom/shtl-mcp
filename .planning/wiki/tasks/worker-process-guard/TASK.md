**Status:** done
**Тип:** bugfix кода под существующее намерение (raw: «Instance — один запущенный Unity Editor»,

## Находка (как всплыло)

При прогоне тестов через MCP curl по порту из `registry.json` (9731) ответил «unknown jobId», хотя job
существовал. Диагностика: запись shtl-mcp в реестре попеременно перезаписывалась ДВУМЯ процессами —
главным редактором (pid 64351, порт 9730) и AssetImportWorker4 (pid 36168, порт 9731). lsof подтвердил:
оба живых воркера TestProject~ (AssetImportWorker2/4) держали собственные MCP-листенеры (9732/9731).

**Корень:** `[InitializeOnLoad]`-ctor `ShtlMcpBootstrap` исполняется в ЛЮБОМ процессе, загружающем
editor-сборки, включая AssetImportWorker'ы (batchmode-помощники импорта). Guard'а на «я главный
редактор» не было → воркер поднимал полный сервер. Дальше каскад:

1. `RegistryStore.Upsert` ключуется по `projectPath`, а у воркера он ТОТ ЖЕ, что у редактора →
   heartbeat'ы (фоновые, раз в секунду) перетирают запись друг друга; registry «мигает» pid/port.
2. `ServerName.Resolve` дедупит только ЧУЖИЕ пути (`existing == projectPath` → то же имя) → воркер
   получает то же `serverName` — коллизия, которую дедуп по дизайну не ловит.
3. `EnsureStarted` при дрейфе порта зовёт `claude mcp add --scope user` → воркер мог перерегистрировать
   глобальную запись клиента на СВОЙ порт (клиент подключается к воркеру, а не к редактору).

Порт-аллокация при этом честно разводила процессы по портам (9730/9731/9732) — маскировало баг:
редактор работал, ломался только discovery через реестр.

## Фикс

`ShtlMcpBootstrap` static ctor: ранний `return` при `AssetDatabase.IsAssetImportWorkerProcess()` —
воркер не вешает подписки и не стартует ничего. Единственная точка входа (других `InitializeOnLoad`
в пакете нет), guard закрывает listener + registry + re-register разом.

Не расширяли: guard общего batchmode (CLI `-batchMode -runTests` и т.п.) — отдельный вопрос, намерение
для CI-сценария в raw не зафиксировано (см. journal, открытый вопрос).

## Тест-гэп

EditMode-тест не может исполниться в контексте AssetImportWorker (Test Runner живёт в главном
редакторе), а сам guard — тавтологический вызов Unity API без своей логики → автотест неуместен
(глобальные принципы: простой багфикс без теста). Верификация — ручная (AC-1), зафиксирована в journal.
