# journal — create-asset

## 2026-07-30 — реализация

Тул намеренно узкий: **создать** ассет и ничего больше. Всё остальное уже есть — поля правит
`modify_object` (включая ссылки, после `objref-write`), удаление и перемещение — `delete_asset` /
`move_asset`. Поэтому в API нет ни начальных значений полей, ни материал-специфики (keywords,
render queue): это разошлось бы с философией тонкого ядра, зафиксированной в F3.

Инстанцирование разведено по трём веткам:
- `Material` — единственный тип с обязательным параметром (`shader`), потому что материал без
  шейдера бессмысленен и Unity молча даст розовый;
- наследники `ScriptableObject` — `CreateInstance` (обычный `new` для них не работает);
- остальное — только если есть конструктор без параметров; `Texture2D`/`RenderTexture` сюда не
  попадают осознанно (нужны размеры и формат — это уже не «создать пустой ассет»).

Резолв типа переиспользует `TypeResolve.Find` с базой `UnityEngine.Object`, поэтому подсказки при
опечатке в имени работают так же, как у `add_component`.

## Верификация

`Unity 2022.3.62f3 -batchmode -runTests -testPlatform EditMode` (без `-quit`) на `TestProject~`:
**220 passed / 0 failed** (было 216, +4 кейса).

Главный тест — сквозной: `create_asset` создаёт материал с `Unlit/Texture`, затем `modify_object`
правит поле соседнего ассета. Это тот самый путь, ради которого тул заведён: раньше он требовал
Editor-скрипта в host-проекте.
