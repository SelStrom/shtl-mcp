## Находка (как всплыло)

В host-проекте PerfectWar Unity-проект вложен в репозиторий (`repo/Client/PerfectWar/`), а
`CLAUDE.md` живёт в корне репо. Дашборд предлагал добавить крошку в
`repo/Client/PerfectWar/CLAUDE.md`: `DashboardWindow.HostProjectRoot()` берёт
`Directory.GetParent(Application.dataPath)` (корень Unity-проекта), а `HostBreadcrumb.TargetPath`
просто клеил к нему `CLAUDE.md`. Claude Code при старте грузит `CLAUDE.md` от корня репозитория —
крошка в корне вложенного Unity-проекта в типовой сессии не видна, т.е. cold-start НЕ закрывается,
хотя статус в дашборде показывал бы «✓».

## Фикс

`HostBreadcrumb.ResolveTargetPath(unityProjectRoot)` вместо `TargetPath`: кандидаты — `CLAUDE.md`
на каждом уровне от git-корня (директория с `.git`; и dir, и file — worktree/submodule) вниз до
корня Unity-проекта. Приоритет:

1. файл с уже добавленным маркером — идемпотентность для хостов, где крошка добавлена старой
   версией в корень Unity-проекта (статус «✓», без дубля во втором файле);
2. существующий `CLAUDE.md`, ближайший к git-корню (дописывать в существующий, а не плодить новый);
3. git-корень — файл будет создан;
4. Unity-проект вне git-репозитория — прежнее поведение, корень Unity-проекта.

Дашборд показывает разрешённый путь в foldout и в модале подтверждения (как раньше, но теперь
путь честный).

## Acceptance

- AC-1: для вложенного Unity-проекта с `CLAUDE.md` в git-корне целевой путь = `<gitRoot>/CLAUDE.md`.
- AC-2: маркер, добавленный старой версией в корень Unity-проекта, даёт статус «✓» (без дубля).
- AC-3: без `.git` вверх по цепочке — прежнее поведение (корень Unity-проекта).
- AC-4: полный EditMode-сьют зелёный.
