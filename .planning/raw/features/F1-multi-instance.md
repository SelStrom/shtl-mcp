# F1 — Мульти-инстансовость и discovery

**Требование #1.** Один MCP, запущенный из инстанса Unity, сосуществует с
другими инстансами; модель легко понимает, какому инстансу слать команды.
Поддержка клонов и git-worktrees одного проекта.

## Acceptance criteria

- **AC1.1** — Два и более одновременно запущенных Unity (разные пути) поднимают
  независимые серверы на разных портах без коллизий.
- **AC1.2** — Каждый инстанс пишет/обновляет запись в `~/.unity-mcp/registry.json`
  с heartbeat; протухшие записи отсеиваются по `lastHeartbeat`.
- **AC1.3** — `serverName` уникален: по умолчанию `unity-<projectName>`; при
  коллизии имени с другим живым путём — суффикс `-<hash4(projectPath)>`.
- **AC1.4** — Порт детерминирован по `projectPath` и стабилен между рестартами
  Unity (если свободен) → ранее добавленная `claude mcp add`-запись продолжает
  работать.
- **AC1.5** — Прочитав реестр, модель регистрирует инстанс одной командой
  `claude mcp add --transport http <serverName> http://127.0.0.1:<port>/mcp`;
  инструменты приходят с префиксом `mcp__<serverName>__*`.
- **AC1.6** — Инструмент `status` возвращает полную идентичность инстанса; каждый
  ответ инструмента включает `projectName`.
- **AC1.7** — Клон/worktree того же продукта различимы (разные `serverName`,
  разные порты), модель адресует их раздельно по префиксу.

## Out of scope
- Роутер/брокер-процесс (отвергнут ради самодостаточности и отказоустойчивости).
- Одновременное открытие одного и того же пути проекта дважды (запрещено Unity).
