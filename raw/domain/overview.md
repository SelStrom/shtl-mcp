# Домен: shtl-mcp

## Назначение
Лёгкий **самодостаточный** MCP-сервер для Unity Editor. Даёт LLM-агентам (через
Claude Code, в перспективе — другие MCP-клиенты) полноценный контроль над
запущенным инстансом Unity: компиляция, ассеты, префабы, сцены, play/edit,
тесты — **без внешних процессов-мостов** (отличие от всех существующих
Unity-MCP, которые используют трёхзвенную схему AI ↔ внешний сервер ↔ плагин).

## Ключевые сущности

- **Instance (инстанс)** — один запущенный Unity Editor с активным MCP-сервером.
  Идентичность: `projectName`, `projectPath`, `unityVersion`, `port`, `pid`,
  `mode` (edit/play), `serverName`. Один путь проекта = максимум один инстанс
  (Unity держит `Temp/UnityLockfile`).
- **Registry (реестр)** — общий файл `~/.unity-mcp/registry.json`, агрегирующий
  живые инстансы (heartbeat). Источник истины о том, «какие инстансы есть и на
  каких портах».
- **Control channel** — управляющие флаги `~/.unity-mcp/<serverName>.cmd`, которые
  watchdog исполняет в главном потоке (напр. `restart`). Канал работает, даже
  когда HTTP-сервер недоступен (это файл, как и реестр).
- **Transport** — Streamable HTTP, эндпойнт `POST /mcp`, JSON-RPC 2.0,
  минимальный набор методов MCP (`initialize`, `tools/list`, `tools/call`).
- **Dispatcher** — мост «фоновый поток ↔ главный поток Unity». Очередь команд,
  исполняемых строго в главном потоке (Unity API не потокобезопасен).
- **Job (асинхронная задача)** — единица работы, переживающей domain reload
  (recompile, вход/выход play, run_tests, тяжёлый импорт). Идентифицируется
  `jobId`; статус/результат хранится в `SessionState` и переживает reload.
- **Tool (инструмент)** — зарегистрированная команда MCP (атрибут `[McpTool]`).
  Тонкое ядро + escape hatches (`run_csharp`, `execute_menu_item`).
- **Dashboard** — единственное окно UI Toolkit; информационное.

## Жёсткие инварианты (нарушать нельзя)

- **INV-1 — Play+Edit.** Каждый инструмент корректно работает и в Edit, и в Play
  mode. Команды, триггерящие domain reload, реализованы как async-job и
  переживают reload.
- **INV-2 — Самодостаточность.** Установка = только Unity-пакет. Ноль артефактов
  в папке LLM-клиента (скиллы/плагины). Единственное касание клиента — конфиг
  `claude mcp add`. Ни одного внешнего процесса/демона/нативного бинаря.
- **INV-3 — Однозначность инстанса.** Модель всегда детерминированно определяет,
  какому инстансу адресована команда (префикс инструментов = `serverName`,
  уникальный по пути). Каждый ответ инструмента несёт идентичность инстанса.
- **INV-4 — Одно окно.** MCP не открывает никаких окон/попапов, кроме
  единственного дашборда, и не открывает его принудительно.
- **INV-5 — Самовосстановление.** При живом Unity сервер восстанавливается
  (watchdog) после domain reload/сбоя listener без участия человека. Модель может
  детерминированно инициировать форс-рестарт через control-flag, пока главный
  поток Unity тикает.

## Ограничения

- Unity 2022 LTS и выше; C# only; .NET Standard 2.1 / Mono; Newtonsoft.Json.
- Запуск самого Unity — **вне зоны MCP** (решение: watchdog + reconnect, без
  запуска Unity моделью, без внешнего демона).
- Итерация 1 — Claude Code. HTTP-ядро держится клиент-агностичным
  (Cursor/Desktop — последующие итерации).
