# F7 — Самоописываемое восстановление (discoverability)

**Требование #2 (доставка знания).** Использующая модель должна узнать, как
поднять сервер после падения — **без доступа к dev-репозиторию shtl-mcp** и
**без работающего MCP-канала** (сервер лёг → tools/list, `status`, описания
недоступны). Защита по трём каналам + опциональная host-крошка.

Решение по cold-start (зафиксировано): **вариант A** — строго самодостаточно по
умолчанию; полное закрытие cold-start — опционально, только с явного согласия
(AC7.4).

## Жёсткое ограничение канала
При мёртвом сервере доставить инструкцию через MCP физически нельзя. Работают
только: (1) файловая система, (2) пре-брифинг в момент подключения, (3) конфиг
клиента. Durable-бэкстоп — обязательно на ФС.

## Acceptance criteria

- **AC7.1 — Самодокументируемый реестр (durable, primary).** Сервер при старте
  встраивает в `~/.unity-mcp/registry.json` блок `recovery` (`controlFlagPath`,
  пошаговые `steps`, готовые команды restart/reconnect). Пишет **пакет, не
  listener** → переживает падение сервера. Это файл, который модель и так читает
  первым, чтобы найти инстанс/порт → натуральная точка обнаружения. Опц. дубль —
  человекочитаемый `~/.unity-mcp/RECOVERY.md`.
- **AC7.2 — Пре-брифинг через MCP.** `initialize.instructions` и описание `status`
  содержат: «если стану недоступен → прочитай `~/.unity-mcp/registry.json` →
  `recovery`». Покрывает основной кейс — падение в середине сессии у модели,
  которая уже подключалась.
- **AC7.3 — recoveryHint.** Ответы инструментов (пока сервер жив) несут поле
  `recoveryHint` со ссылкой на реестр — закрепляет, где смотреть.
- **AC7.4 — Опциональная host-крошка (opt-in, только с явного согласия).** Дашборд
  и документированный онбординг могут **предложить** добавить в host-проект одно
  из: (а) однострочный recovery-указатель в его `CLAUDE.md`, либо (б) минимальный
  recovery-скилл. По умолчанию — **ничего** (INV-2). Применяется только по явному
  согласию; закрывает cold-start (свежая сессия, сервер уже мёртв, модель ни разу
  не подключалась).

## Out of scope
- Авто-добавление чего-либо в host-проект **без** согласия (запрещено INV-2).
- Доставка инструкции через MCP-канал при мёртвом сервере (физически невозможно).
